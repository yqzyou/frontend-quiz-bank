## 题目
下列哪些 Slack / Discord 操作会让远程同事更舒服？（多选）

## 选项
A. 把"你好 / 我有事说 / 事情内容 / 谢谢"四句话合并成一条消息发送，用 Shift+Enter 分行 ✓
B. 用 thread 回复而不是 channel 顶层，避免污染主频道 ✓
C. 用 /status 或 emoji 标记"不在 / 在会议"，避免别人误以为你 ignore ✓
D. @here 用在真正紧急的情况（生产事故、阻断发布），不用来"提醒一下" ✓

## 解析
**Slack 礼仪 9 条**：

1. **一条消息 = 一个完整想法**：用 Shift+Enter 写多行，不要发 5 条碎片（选项 A 的做法）。每条碎片让对方手机响一次，且脱离上下文
2. **Threads 是默认**：在 thread 里讨论，主频道只发广播
3. **@mention 而不是 @here / @channel**：除非真的紧急
4. **状态先行**：请假、深度工作、会议中 → 设置 status
5. **emoji 反应代替 "ok"**：✅/👍/👀 比"收到，谢谢"更高效
6. **不在凌晨 / 周末 ping**：用 schedule send，让对方周一 9 点看到
7. **链接给上下文**：粘贴 PR 时写一句话说明"看 line 45 的 SM-2 实现"
8. **DM vs Channel**：除非真的私密，优先 channel → 其他人能学到
9. **避免"你在线吗？"**：直接说事，对方有时间就回

**Slack vs Discord vs Email**：

| 工具 | 适用 | 不适用 |
|------|------|--------|
| Slack | 实时问答、轻量同步 | 长篇决策（用文档） |
| Discord | 社区、语音会议 | 严肃工作通知（无审计） |
| Email | 对外、正式、可存档 | 内部紧急沟通 |
| GitHub issue | 决策、bug、feature | 闲聊 |
| Notion / Confluence | 长期文档 | 临时讨论 |

**典型反模式**：
- "Hi"（然后等对方回"hi"再说事 → 浪费一来一回）
- "你方便开个会吗？"（不说要聊什么）
- 在 #general 频道 @channel 推广个人项目（用 #random）
