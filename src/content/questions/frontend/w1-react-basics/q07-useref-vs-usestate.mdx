## 题目
关于 `useRef` 与 `useState`，下列说法正确的有哪些？（多选）

## 选项
A. 改 `ref.current` 不会触发重渲染，因此适合存"对 UI 无影响的可变值"（如计时器 id、Web3 钱包实例） ✓
B. 两者都能在组件多次渲染间保持值，但只有 `useState` 的变化会触发 reconciliation ✓
C. `useRef(initialValue)` 等价于 `useState({ current: initialValue })[0]`
D. `useRef` 比 `useState` 更快，应优先用 `useRef`

## 解析
**核心区别**：

```jsx
const [count, setCount] = useState(0);  // setCount → 重渲染
const timerRef = useRef<number>();      // timerRef.current = 1 → 不重渲染
```

| 维度 | useRef | useState |
|------|--------|----------|
| 渲染时初始化 | 是（initialValue 只在首次生效） | 是 |
| 跨渲染保持值 | 是 | 是 |
| 修改触发重渲染 | **否** | 是 |
| 读取时机 | 渲染期间也能读 | 渲染期间用 state 值 |
| 适用 | DOM 引用、第三方实例、计时器 | 影响视觉的状态 |

**典型场景**：

```jsx
function WalletConnector() {
  const [address, setAddress] = useState('');
  const providerRef = useRef<EIP1193Provider | null>(null);

  useEffect(() => {
    providerRef.current = detectProvider();
    // 不需要触发表单 UI 变化
  }, []);

  const connect = async () => {
    const addr = await providerRef.current?.request({ method: 'eth_requestAccounts' });
    setAddress(addr[0]); // 触发渲染显示地址
  };

  return <button onClick={connect}>{address || '连接'}</button>;
}
```

**为什么 D 错？** 性能不是优劣标准——选 ref/state 取决于"UI 是否依赖该值"。错用 ref 存 UI 状态会导致显示与数据脱节（state 变了 UI 没变）。

**为什么 C 不严谨？** ref 的 `current` 在后续渲染中**不会被重置**（initialValue 只用一次）；而 `useState({ current: ... })` 创建的字面量每次渲染都新建，但 React 内部会保留首次创建的 state 值——所以**值行为**等价，**API 语义**不等价。
