## 题目
请谈谈 React 虚拟 DOM 解决了什么问题，又有哪些它**不擅长**的场景。

## 解析
虚拟 DOM（VDOM）的本质是用 JavaScript 对象描述 UI，在状态变化后通过 diff 算法计算最小变更，再批量提交到真实 DOM。

## 参考答案
**虚拟 DOM 解决的问题：**

1. **声明式抽象**：开发者描述「UI 应该是什么样」，而不是「如何一步步改 DOM」，心智负担显著降低。
2. **跨平台渲染**：同一棵组件树可以渲染到 DOM、Native、SSR、Canvas 甚至终端。
3. **批量更新**：状态变化先在内存里 diff，最后一次提交，避免频繁触发布局/绘制。
4. **diff 复杂度可控**：通过「同层比较 + 类型不同直接替换 + key 提示」三个假设，把 diff 降到 O(n)。

**虚拟 DOM 不擅长的场景：**

1. **超大规模列表（万级单元格）**：diff 本身有成本，单纯靠 VDOM 不如虚拟滚动 + 视口裁剪。常见做法是 `react-window` / `react-virtual` 配合。
2. **高频实时画布（游戏、可视化）**：每帧重算 VDOM 是浪费，更适合直接操作 Canvas / WebGL / SVG，或用 `useSyncExternalStore` 把外部数据源接入。
3. **细粒度动画**：动画帧之间不需要 diff，应交给 CSS / Web Animations API / GSAP。
4. **强命令式交互（拖拽、手势）**：通常用 ref 直接操作 DOM，绕开 VDOM。

**关键认知**：虚拟 DOM 不是「最快」的方案，而是「在大多数业务场景下足够快 + 抽象足够好」的方案。React 19 的 React Compiler 已经能自动 memoize，进一步降低手动优化的需求。
